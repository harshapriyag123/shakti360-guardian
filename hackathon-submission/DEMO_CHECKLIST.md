# Demo and submission checklist

## Setup

- [ ] Use this repository and the published 0.1.0 Play; do not republish or edit the implementation.
- [ ] Confirm Python 3.11+, existing Rote authentication and process-execution eligibility off camera. Do not install adapters or bypass access policy.
- [ ] Inspect the pinned artifact and read its required usage disclosure. Generic service/write summaries do not cover Python-internal effects.
- [ ] Run the setup in [DEMO_SCRIPT.md](DEMO_SCRIPT.md), choosing a fresh ignored output directory and keeping scratch data inside the repository.
- [ ] Verify the installed local name maps to the published artifact before using its dry-run DAG.

## Rehearsal

- [ ] Run `python3 -B -m unittest discover -s rote/shaktisafe-brief -p test_shaktisafe.py -v` with `TMPDIR` set as in the demo setup; expect 12 passing tests.
- [ ] Rehearse Houston first run and same-context refresh before the outing window expires. Inspect actual timestamps and changes.
- [ ] Rehearse Chennai coverage limitations and the explicitly synthetic offline failure example.
- [ ] Confirm the brief and failure screenshot filenames against [assets/README.md](assets/README.md).
- [ ] Fit narration to 2–3 minutes; label edits that condense waiting time. Do not present playback duration as measured runtime.

## Recording and privacy review

- [ ] Use a neutral prompt, generic cities, clean browser window and large font.
- [ ] Hide account details, notifications, emails, tokens, usernames, history and private paths, including title bars and transitions.
- [ ] Keep synthetic banners, STALE labels, timestamps and unsupported statuses visible.
- [ ] Show the actual five-stage ledger and distinguish a dry-run plan from executed results.
- [ ] Explain NWS coverage, modeled air quality, external provider requests, persistent files and process-policy restrictions.
- [ ] Do not imply missing alerts mean all clear or that token savings were independently measured.

## Links, backups and submission

- [ ] Open the [pinned Community URL](https://play.modiqo.ai/harshapriyag123/shaktisafe-brief@0.1.0) and [GitHub source](https://github.com/harshapriyag123/shakti360-guardian/tree/main/rote/shaktisafe-brief) from a clean browser session.
- [ ] Collect genuine backup screenshots listed in the assets README; label any historical output and its date.
- [ ] Confirm public access to the final video after uploading it through the actual submission flow. No video upload or video URL is claimed by this package.
- [ ] Verify submission requirements, deadline and video permissions on the actual hackathon form; this package does not invent them.
- [ ] Review title, pitch, judging table, source link and social drafts. Social posts remain drafts until separately sent.
- [ ] Check `git diff --check`, review the documentation-only diff and confirm unrelated files are untouched.
- [ ] Commit with `docs: add ShaktiSafe hackathon submission package`; push only the current configured branch with existing authentication.
- [ ] Submit the final package and video through the hackathon form. Publication of the Play alone is not evidence that a hackathon form was submitted.
- [ ] Decide how long to retain recordings, source outputs and baselines, and manually remove them when no longer needed.
